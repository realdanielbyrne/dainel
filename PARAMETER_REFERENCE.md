# SharePoint Storage Investigation - Parameter Reference Card

## Quick Parameter Guide

### Authentication Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `AdminEmail` | String | `dbyrne@rpmxconstruction.com` | Administrator email for authentication |
| `ClientId` | String | `ed6e79b0-8985-499d-8718-4a01cf6c9129` | Azure AD app registration client ID |
| `Tenant` | String | `rpmxconstruction.com` | Tenant domain name |

**Example:**
```powershell
.\Investigate-SharePointStorage.ps1 -AdminEmail "admin@contoso.com" -Tenant "contoso.com"
```

### Analysis Scope Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `DaysBack` | Int | `4` | Number of days for recent audit log search |
| `OutputPath` | String | `"."` | Directory for CSV export files |
| `TopSitesForRecycleBin` | Int | `50` | Number of sites to analyze for recycle bins |
| `TopSitesForVersionReports` | Int | `10` | Number of sites to queue version history reports |

**Example:**
```powershell
.\Investigate-SharePointStorage.ps1 -DaysBack 7 -OutputPath "C:\Reports" -TopSitesForRecycleBin 25
```

### Feature Control Parameters (Switches)

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `SkipPeriodAnalysis` | Switch | `$false` | Skip 1/3/6 month uploader analysis |
| `SkipRecycleBinAnalysis` | Switch | `$false` | Skip recycle bin storage analysis |
| `SkipVersionReports` | Switch | `$false` | Skip version history report queuing |

**Example:**
```powershell
# Skip expensive analyses
.\Investigate-SharePointStorage.ps1 -SkipPeriodAnalysis -SkipRecycleBinAnalysis

# Enable all features (default)
.\Investigate-SharePointStorage.ps1

# Enable specific feature that's normally skipped
.\Investigate-SharePointStorage.ps1 -SkipVersionReports:$false
```

## Parameter Impact on Output

### CSV Files Generated by Feature

| Feature | Parameter | CSV Files |
|---------|-----------|-----------|
| **Core** | (always) | 00-05, 08-13 (13 files) |
| **Recent uploaders** | `DaysBack` | 06-07 (already counted) |
| **Period analysis** | `-SkipPeriodAnalysis` | 14-19 (6 files) |
| **Recycle bins** | `-SkipRecycleBinAnalysis` | 20 (1 file) |
| **Version history** | `-SkipVersionReports` | 21 (1 file)* |

*Requires Microsoft.Online.SharePoint.PowerShell module

### Execution Time Factors

| Feature | Impact | Affected By |
|---------|--------|-------------|
| Core site/OneDrive | Low | Tenant size |
| Fastest growing | Medium | Audit log size, months analyzed |
| Recent uploads | Low | `DaysBack` value |
| **Period analysis** | **HIGH** | Audit log size (3 queries: 1/3/6 months) |
| **Recycle bin** | **MEDIUM-HIGH** | `TopSitesForRecycleBin`, site responsiveness |
| Version history | Low | Just queues jobs (async) |

## Skip Parameter Logic

### Default Behavior (No Skip Flags)
```powershell
.\Investigate-SharePointStorage.ps1
```
- ✅ Period analysis runs (1/3/6 months)
- ✅ Recycle bin analysis runs (top 50 sites)
- ✅ Version history queued (top 10 sites, if module available)

### Selective Skipping
```powershell
.\Investigate-SharePointStorage.ps1 -SkipPeriodAnalysis
```
- ❌ Period analysis skipped
- ✅ Recycle bin analysis runs
- ✅ Version history queued

### Skip All Optional Features
```powershell
.\Investigate-SharePointStorage.ps1 `
    -SkipPeriodAnalysis `
    -SkipRecycleBinAnalysis `
    -SkipVersionReports
```
- ❌ Period analysis skipped
- ❌ Recycle bin analysis skipped
- ❌ Version history skipped
- ✅ Core features still run

### Force-Enable Skipped Features
```powershell
# If you want to be explicit about enabling
.\Investigate-SharePointStorage.ps1 `
    -SkipPeriodAnalysis:$false `
    -SkipRecycleBinAnalysis:$false `
    -SkipVersionReports:$false
```

## Scope Parameters

### TopSitesForRecycleBin

Controls how many sites to check for recycle bin storage.

| Value | Use Case | Estimated Time |
|-------|----------|----------------|
| `5` | Quick test | 2-3 minutes |
| `10` | Daily check | 5-7 minutes |
| `25` | Weekly check | 10-15 minutes |
| `50` | Monthly report (default) | 20-30 minutes |
| `100` | Deep cleanup analysis | 40-60 minutes |

**Example:**
```powershell
# Quick daily check
.\Investigate-SharePointStorage.ps1 -TopSitesForRecycleBin 10

# Thorough monthly analysis
.\Investigate-SharePointStorage.ps1 -TopSitesForRecycleBin 100
```

### TopSitesForVersionReports

Controls how many version history reports to queue.

| Value | Use Case | Notes |
|-------|----------|-------|
| `3` | Testing | Minimal queue |
| `5` | Targeted analysis | Key sites only |
| `10` | Standard (default) | Balanced approach |
| `20` | Comprehensive | Full coverage |

**Important:** Reports take 1-3 days to generate!

**Example:**
```powershell
# Conservative approach
.\Investigate-SharePointStorage.ps1 -TopSitesForVersionReports 5

# Comprehensive analysis
.\Investigate-SharePointStorage.ps1 -TopSitesForVersionReports 20
```

### DaysBack

Controls recent audit log search range.

| Value | Use Case | Audit Records |
|-------|----------|---------------|
| `1` | Daily monitoring | Minimal |
| `4` | Default recent activity | Low-Medium |
| `7` | Weekly check | Medium |
| `30` | Monthly report | High |
| `90` | Maximum E3 retention | Very High |
| `365` | Maximum E5 retention | Extremely High |

**Example:**
```powershell
# Daily check
.\Investigate-SharePointStorage.ps1 -DaysBack 1

# Use full E5 retention
.\Investigate-SharePointStorage.ps1 -DaysBack 365
```

## Troubleshooting Parameter Issues

### "Parameter not recognized"
Check spelling and capitalization:
```powershell
# ❌ Wrong
.\Investigate-SharePointStorage.ps1 -skipPeriodAnalysis

# ✅ Correct
.\Investigate-SharePointStorage.ps1 -SkipPeriodAnalysis
```

### "Cannot convert value"
Check parameter type:
```powershell
# ❌ Wrong (string for integer)
.\Investigate-SharePointStorage.ps1 -DaysBack "seven"

.\Investigate-SharePointStorage.ps1 -DaysBack 7
```

## Best Practices

1. **First run:** Use defaults to get full picture
2. **Regular monitoring:** Use skip flags to reduce time
3. **Large tenants:** Start with small scope, increase gradually
4. **Off-peak hours:** Run intensive analyses during low usage
5. **Output organization:** Use `-OutputPath` for organized storage
6. **Version history:** Queue reports early, check back in 3 days
7. **Testing:** Always test with limited scope first
